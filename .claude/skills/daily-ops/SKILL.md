# daily-ops

## いつ使う
毎日、成果物ができたあと。人間に渡す作業があるとき。

## 並び（この順で書く）
見出し → 所要時間 → 人間への質問（あるときだけ）→ 作業（時間帯ごと）→ 報告 → 明日の予告

## 書き方
1. ファイル名は ops/dayNN.md（NN は Day 番号を2桁。例: day02.md）。見出しは「# Day N（M/D 曜）お前がやること」。見出しの N と M/D はゼロ埋めしない。曜は漢字1字（月 火 水 木 金 土 日）。例: `# Day 2（10/17 土）お前がやること`
2. 見出しの次の行に合計所要時間（分）を書く（例: `所要: 合計12分`）。README.md に書いた人間の作業時間の上限を超えるなら、期限に効かない作業から削って翌日に回す
3. 人間への質問があるときは、所要時間の次、作業より前に「## 人間への質問」を置き、1問だけ書く（1日1問）。数字・日付・番号で答えられる形にする。答えは報告の穴埋め1行の末尾に `Q1=` を足して受け取る。質問が無い日はこの項を置かない
   - 聞くことが複数あるときは、次の順で1つ選ぶ。残りは翌日以降に回す: (1) 判断ルールに関わるもの（判定に要る数字・日付・状態）→ (2) 指標の出どころ（報告の数字を、どのサービスのどの画面で見るか）→ (3) その他
   - 指標の出どころを聞く型: `Q1. 報告の《指標》は、どの画面で見た数字か。1 = 《確かめた画面の経路》 ／ 2 = それ以外の画面（報告にその画面のスクショを添える）／ 3 = 見ていない（その指標は「-」と書く）`。確かめた経路が無いときは 1 を置かない（番号は 2・3 のまま）。答えは README.md の「指標の定義」に書き足す
4. 作業は時間帯ごとに分け、番号をつけ、順番どおりに並べる。各作業に所要時間（分）をつける
5. 各作業は「どこで → 何を → 何を貼る／押す → 終わったら何を報告する」の形。貼る文面はファイル名と見出しで指す（例: posts/x/2026-10-16.md の「## 20:00 進捗」の下から次の見出しの前まで、全部）。ファイルの最後の見出しの本は、次の見出しが無いので「…の下から、ファイルの終わりまで、全部」と書く
6. 人間に選ばせない。選択肢が要るときは AI が推奨を1つ決めて「変えるなら言ってくれ」と添える
7. 設定変更は画面の経路を書く（例: 設定 → 記事設定 → ○○をOFF）。確かめていない経路は推測で書かない
8. 画面が違ったとき: 画面を操作する作業（アプリやサイトの画面を開く・押す・読む・貼るもの）には、経路を確かめていてもいなくても、すべて末尾に次の1文を一字も変えずに書く。「見つからなければ、その画面のスクショを貼って止まる」。「報告」の項も画面で数字を読む作業なので、項の最後に同じ1文を書く。人間に探させない
9. 最後に「報告」の項を置く。何の数字を、どこで見るかを書き（数え方は README.md の「指標の定義」に従う）、次の穴埋めの1行で渡す: `M/D 投稿数= imp= フォロワー= PV= 購入= 売上= 作業分= 警告=`（例: `10/17 投稿数= imp= フォロワー= PV= 購入= 売上= 作業分= 警告=`）。日付は省かない
   - 警告= は、その日に受けたプラットフォームからの警告・制限の通知の件数（無ければ 0）。1以上なら、通知の画面のスクショを添えてもらう
   - 同じ日に2回報告してもらうとき（例: 昼と夜）は、2回目はその日の累計（その日の分の合計。フォロワーはその時点の数）で書くと指示する
10. 明日以降の予告を3行以内で

## 禁止
- 「適当に」「いい感じに」「必要なら」
- 1作業に複数の判断を含めること
- 人間に文章を書かせること（返信・問い合わせの文面もAIが用意する）
- 見たことのない画面のボタン名を、あるものとして書くこと
