# daily-ops

## いつ使う
毎日、成果物ができたあと。人間に渡す作業があるとき。

## 並び（この順で書く）
見出し → 所要時間 → 人間への質問（あるときだけ）→ 作業（時間帯ごと）→ 報告 → 明日の予告

## 書き方
1. ファイル名は ops/dayNN.md（NN は Day 番号を2桁。例: day02.md）。見出しは「# Day N（M/D 曜）お前がやること」。見出しの N と M/D はゼロ埋めしない。曜は漢字1字（月 火 水 木 金 土 日）。例: `# Day 2（10/17 土）お前がやること`
2. 見出しの次の行に合計所要時間（分）を書く（例: `所要: 合計12分`）。README.md に書いた人間の作業時間の上限を超えるなら、期限に効かない作業から削って翌日に回す
3. 人間への質問があるときは、所要時間の次、作業より前に「## 人間への質問」を置き、1問だけ書く。数字・日付・番号で答えられる形にする。答えは報告の穴埋め1行の末尾に `Q1=` を足して受け取る。質問が無い日はこの項を置かない
4. 作業は時間帯ごとに分け、番号をつけ、順番どおりに並べる。各作業に所要時間（分）をつける
5. 各作業は「どこで → 何を → 何を貼る／押す → 終わったら何を報告する」の形。貼る文面はファイル名と見出しで指す（例: posts/x/2026-10-16.md の「## 20:00 進捗」の下から次の見出しの前まで、全部）
6. 人間に選ばせない。選択肢が要るときは AI が推奨を1つ決めて「変えるなら言ってくれ」と添える
7. 設定変更は画面の経路を書く（例: 設定 → 記事設定 → ○○をOFF）。確かめていない経路は推測で書かない
8. 画面が違ったとき: 画面を操作する作業（アプリやサイトの画面を開く・押す・読む・貼るもの）には、経路を確かめていてもいなくても、すべて末尾に次の1文を一字も変えずに書く。「見つからなければ、その画面のスクショを貼って止まる」。人間に探させない
9. 最後に「報告」の項を置く。何の数字を、どこで見るかを書き（数え方は README.md の「指標の定義」に従う）、次の穴埋めの1行で渡す: `M/D 投稿数= imp= フォロワー= PV= 購入= 売上= 作業分=`（例: `10/17 投稿数= imp= フォロワー= PV= 購入= 売上= 作業分=`）。日付は省かない
10. 明日以降の予告を3行以内で

## 禁止
- 「適当に」「いい感じに」「必要なら」
- 1作業に複数の判断を含めること
- 人間に文章を書かせること（返信・問い合わせの文面もAIが用意する）
- 見たことのない画面のボタン名を、あるものとして書くこと
